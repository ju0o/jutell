# Request Builder — 요청 만들기 템플릿

## 이 폴더는 무엇인가요?

막연한 요구를 AI Agent가 이해할 수 있는 요청서로 바꾸는 Markdown 템플릿 모음입니다.

JuTell은 Agent를 대신 실행하거나 Prompt를 자동으로 보내지 않습니다. 완성된 요청문을 복사해서 사용 중인 AI Agent(Codex, Claude Code, OpenCode 등)에 직접 붙여넣으면 됩니다.

## 사용 방법 (3단계)

1. 하고 싶은 일과 가장 가까운 템플릿을 고릅니다.
2. `[ ]` 선택지에 체크하고, 빈칸에는 쉬운 말로 적습니다. 모르는 항목은 **비워 둡니다.**
3. 맨 아래 **최종 요청문**을 복사해 AI Agent에 붙여넣습니다.

## 템플릿 목록

| 템플릿 | 언제 사용하나요? |
|---|---|
| [DESIGN_REQUEST.md](DESIGN_REQUEST.md) | 화면 모양이나 분위기를 바꾸고 싶을 때 |
| [FEATURE_REQUEST.md](FEATURE_REQUEST.md) | 새로운 기능이나 화면을 만들고 싶을 때 |
| [BUG_REPORT_REQUEST.md](BUG_REPORT_REQUEST.md) | 무언가 고장 났거나 이상하게 동작할 때 |
| [PROJECT_PLANNING_REQUEST.md](PROJECT_PLANNING_REQUEST.md) | 프로젝트 전체를 처음 계획할 때 |
| [CODE_REVIEW_REQUEST.md](CODE_REVIEW_REQUEST.md) | 만든 작업을 검토받고 싶을 때 |
| [NEXT_AGENT_HANDOFF.md](NEXT_AGENT_HANDOFF.md) | 다른 AI Agent에게 작업을 넘길 때 |
| [MANUAL_EDIT_GUIDE.md](MANUAL_EDIT_GUIDE.md) | 직접 파일을 수정해야 할 때 |

## 공통 선택지 의미

- **잘 모르겠음** — 해당 항목을 모르며 AI의 도움을 원합니다.
- **정확히 무엇이 문제인지 모르겠음** — 문제는 느끼지만 원인을 특정하지 못합니다.
- **현재 상태 유지** — 이 부분은 지금 그대로 두길 원합니다.
- **요청하지 않음** — 이 항목은 다루지 않길 원합니다.
- **AI가 먼저 확인 후 제안** — 답을 추측하지 말고 먼저 확인한 뒤 선택지를 제안해달라는 뜻입니다.

## 작성 원칙

- 전문 용어, 색상 코드(Hex), CSS, Framework 이름을 몰라도 됩니다. 그런 용어가 필요한 항목은 선택지로 고르거나 `잘 모르겠음`으로 두면 됩니다.
- **모르는 항목은 추측해서 채우지 않습니다.** 빈칸은 AI가 요청서를 읽고 질문해야 할 항목으로 남습니다.
- **사용자가 직접 쓴 사실과 AI의 제안은 구분해서 표시합니다.**

## 프로젝트 경로 안내 주의

템플릿 안에 "파일은 `src/css/`에 있음", "`npm run dev`로 실행함" 같은 내용을 임의로 채우면 안 됩니다. 실제 프로젝트 구조를 확인하기 전에는 특정 경로나 실행 명령을 확정해 적지 않고, 모르면 `확인 필요`로 남깁니다. AI가 먼저 프로젝트를 확인한 뒤 안내하도록 유도하는 것이 이 템플릿의 목적입니다.

## 요청하기 전에

- 비밀번호, API 키, 토큰, 실제 개인정보는 요청서에 적지 않습니다.
- 기밀 프로젝트 이름이나 저장소 주소가 필요하다면 `내용 요약`만 적습니다.
