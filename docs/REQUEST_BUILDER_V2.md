# Request Builder V2 설계

> 이 문서는 V2의 **설계 초안**입니다. V2는 현재 구현 범위가 아닙니다. 개인 베타 피드백이 모인 뒤에 구현 여부와 우선순위를 결정합니다.

## 1. 목표

V1은 템플릿을 복사해 사용하는 방식입니다. V2는 로컬 관리자 화면에서 템플릿을 선택하고 빈칸을 채우며 요청문을 완성하는 화면을 제공합니다.

**V2는 자동 전송을 포함하지 않습니다.** 완성된 요청문은 사용자가 직접 복사해 사용 중인 AI Agent에 붙여넣습니다. 자동 전송이나 Prompt 수집, 중앙 서버 전송은 설계 대상이 아닙니다.

## 2. 화면 구성 (안)

- 템플릿 목록 → 선택 시 작성 화면
- 8단계 공통 흐름을 단계별 카드로 표시
- 각 단계에 공통 선택지(잘 모르겠음 · 정확히 무엇이 문제인지 모르겠음 · 현재 상태 유지 · 요청하지 않음 · AI가 먼저 확인 후 제안) 적용
- 오른쪽에 실시간 최종 요청문 미리보기 + 복사 버튼

## 3. 입력 저장

- 작성 중 내용은 브라우저 로컬 저장소(localStorage)에 임시 보존 (완료 후 폐기)
- 서버 저장은 하지 않음 — 요청문은 사용자가 복사하는 순간에만 존재
- 민감정보 경고: 저장 전에 비밀번호·API 키·토큰·개인정보가 포함됐는지 사용자가 직접 확인하는 단계 표시

## 4. 검증 단계 (안)

- 최종 요청문 복사 전 목록:
  - 모르는 항목이 빈칸으로 남아 있는지 표시
  - 프로젝트 경로가 확인 없이 확정돼 있는지 경고 (V1 원칙 유지)
  - "현재 상태 유지"나 "요청하지 않음"이 선택된 항목이 있는지 표시

## 5. 범위 밖

- 자동 전송
- Prompt 수집·분석
- 중앙 서버 연동
- Agent별 요청문 문법 변환 (추후 검토)

## 6. 구현 판단 기준

- 개인 베타에서 V1 템플릿을 실제로 사용한 피드백이 있어야 함
- 템플릿 사용 횟수와 작성 완료율이 측정되어야 함 (`docs/USAGE_EFFICIENCY_EXPERIMENTS.md` 참조)
- 위 조건이 없으면 V2를 시작하지 않음
