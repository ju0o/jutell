# JuTell Privacy Principles

## 1. 기본 철학

JuTell는 사용자를 관찰하거나 평가하기 위한 제품이 아니다. 비개발자가 AI Agent 작업 결과를 이해하도록 돕는 제품이며, 현재 실제 연결 Provider는 Codex다. Telemetry가 추가되더라도 목적은 제품 개선으로 제한한다.

투명성을 편의성보다 우선한다. 사용자가 무엇이 기록될 수 있고 무엇이 기록되지 않는지 이해할 수 있어야 한다.

## 2. 코드와 작업 내용

Telemetry는 코드를 읽거나 분석하지 않는다.

Skill이 작업 보고서를 만들기 위해 프로젝트 파일을 확인하는 것과 Telemetry가 데이터를 수집하는 것은 별개의 동작이다. Telemetry에는 프로젝트 코드, 파일 내용, Git diff, 파일 경로를 저장하지 않는다.

## 3. Prompt와 AI 답변

사용자의 Prompt를 저장하지 않는다.

AI 답변 원문과 작업 보고서 원문도 저장하지 않는다. 제품 개선에 필요한 경우에도 원문의 내용이 아니라 허용된 이벤트 종류와 제한된 결과 범주만 고려한다.

## 4. 사용자 식별 금지

사용자를 식별하기 위한 다음 값을 만들거나 수집하지 않는다.

* 사용자 이름과 이메일
* 계정 ID와 사용자별 ID
* 기기 ID와 세션 ID
* IP 주소, 호스트 이름, 위치 정보
* Repository URL과 프로젝트 이름

운영체제 종류처럼 넓은 범주가 허용된 경우에도 다른 정보와 결합해 사용자를 식별하지 않는다.

## 5. 최소 수집

수집 가능한 항목은 공식 Event Registry의 허용 필드로 제한한다.

* 필요한 목적이 있는 정보만 허용한다.
* 자유 텍스트 대신 제한된 범주를 사용한다.
* 원문, 경로, 로그, 토큰을 기록하지 않는다.
* 이벤트마다 필요한 필드만 사용한다.
* 새로운 필드는 개인정보 영향 검토 후 추가한다.

## 6. 사용자 통제

Telemetry는 기본 OFF다.

사용자의 명시적 동의 전에는 이벤트를 만들거나 외부로 전송하지 않는다. 동의하지 않아도 JuTell 보고 기능을 사용할 수 있어야 하며, 사용자는 언제든 끌 수 있어야 한다.

V0.1에서는 동의 화면, 저장, 전송을 구현하지 않는다. 이후 구현 시에도 동의 철회와 삭제 방법을 함께 공개한다.

## 7. 투명성

정책, Event Registry, 수집하지 않는 정보, 삭제 방법을 공개 문서로 관리한다.

설정이나 동의 상태를 숨은 방식으로 바꾸지 않는다. 설정 오류가 발생하면 어떤 안전한 기본값을 사용했는지 짧게 알리되, 설정 파일 전체를 출력하지 않는다.

## 8. 미래 확장 시 기준

로컬 기록, 익명 통계, 중앙 대시보드로 확장할 때도 다음 질문에 답할 수 있어야 한다.

1. 사용자가 사전에 이해하고 동의했는가?
2. 이 정보가 제품 개선에 꼭 필요한가?
3. 개인이나 프로젝트를 다시 알아낼 가능성이 없는가?
4. 사용자가 끄고 삭제할 수 있는가?
5. 원문과 비밀정보가 구조상 제외되어 있는가?

하나라도 답할 수 없으면 해당 확장을 진행하지 않는다.
