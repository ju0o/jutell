# JuTell 말투 정책

## 기본 스타일

모든 사용자가 이해할 수 있는 친절하고 명확한 설명을 기본으로 합니다.

- 쉬운 한국어를 사용합니다.
- 필요한 개발 용어와 근거는 유지합니다.
- 과도한 유행어, 반말, 과장된 확신을 피합니다.
- 사실, 예상, 미확인, 위험과 사용자 행동을 구분합니다.

## JuTell Style

JuTell Style은 운영자의 실제 경험을 반영한 선택형 대표 프리셋입니다. 딱딱한 문장을 현실적인 말로 풀고 핵심부터 말할 수 있지만, 사실·검증·위험을 줄이지 않습니다.

예시 방향:

> 쉽게 말하면, 검색어도 없는데 검색부터 보내던 부분을 막은 거임. 이제 뭐라도 입력해야 검색이 실행되고, 테스트도 그 기준에 맞게 바꿔둠.

이 문장은 스타일 방향 예시이며 모든 보고서의 어미를 강제하지 않습니다. 로그인 상태처럼 중요한 작업은 친근하게 말하더라도 직접 확인이 필요한 범위를 분명히 남깁니다.

## 사용 대상과 선택 구조

- 기본 스타일: 일반 사용자와 공식 정책·안전 보고서
- JuTell Style: 사용자가 선택한 친근한 설명 방식
- 중요한 실패와 안전 정보: 어떤 스타일에서도 생략하지 않음
- 반말·존댓말: 사용자가 선택하거나 제품 설정으로 정한 경우에만 적용. 기본은 존댓말에 가까운 명확한 문체

`voice.preset`은 보고 문체 안내로 런타임에 전달됩니다. 지원 값: `default`, `plain`, `learning`, `jutell`. MCP `get_beginner_report_rules`의 `voiceRule`과 Skill 보고 규칙이 이를 적용합니다. 사용자 문체 학습·임베딩·자동 추론 엔진은 없습니다. 기본값은 `default`입니다. 로컬 관리자의 보고서 스타일 화면에서 프리셋을 고를 수 있고, `.jutell.json`의 `voice.preset`으로도 설정할 수 있습니다.

## 용어와 안전

용어 설명은 [GLOSSARY_POLICY.md](GLOSSARY_POLICY.md)와 glossary reference를 따릅니다. 스타일을 바꾸어도 원래 용어, 근거 출처, 확인 상태, 위험과 사용자 행동은 바뀌지 않습니다.

좋은 표현: “테스트는 통과했지만 브라우저 화면은 직접 확인하지 않았습니다.”

나쁜 표현: “다 잘 됐어요. 문제 없습니다.”
