# JuTell Dogfooding 가이드

JuTell은 자체 검증 실험에 사용됩니다. 이 문서는 그 실험을 운영하는 방법입니다. **이 실험은 공식 검증 결과를 주장하기 위한 것이 아니라, 문제를 찾고 개선 방향을 얻기 위한 것입니다.**

## 실험 원칙

1. JuTell이 만든 결과를 **한 번 더 검토**합니다. JuTell이 만든 보고서이기 때문에 자동으로 정확하다고 받아들이지 않습니다.
2. **자기 검증을 주장하지 않습니다.** "JuTell이 좋다고 JuTell이 판단했다"는 결과는 주장하지 않습니다. 관찰한 사실만 기록합니다.
3. **JuTell 문제와 Agent 문제를 구분합니다.** 같은 결과를 다른 Agent로도 만들어 비교하거나, 문제가 보고서 형식·지침에 있는지 실행 방식에 있는지를 나누어 기록합니다.
4. **기록 우선입니다.** 판단은 기억이 아니라 베타 기록을 근거로 합니다.

## Dogfooding 원칙 (2026-08-04 협업 베타 세션 작업부터)

1. JuTell 개발 작업에도 JuTell을 적용합니다. 이 저장소의 OpenCode 세션은 JuTell MCP와 Skill을 실제로 사용합니다.
2. 매 답변이 완벽하다고 가정하지 않습니다. 확인된 것과 예상된 것을 구분해 읽습니다.
3. JuTell 문제와 OpenCode 자체 문제를 구분합니다. 보고서 형식·지침 문제는 JuTell, 실행·도구 문제는 Agent 문제로 분류합니다.
4. 같은 작업 중 Profile과 Feature를 계속 바꾸지 않습니다. 작업 시작 시점의 설정을 유지합니다.
5. 문제를 발견하면 즉시 기능 수정하기보다 먼저 기록합니다. 기록 후 반복 여부를 확인합니다.
6. 반복되는 문제만 규칙 후보로 승격합니다. 한 번의 관찰로 규칙을 만들지 않습니다.
7. 실제 사용량 근거 없이 토큰 효율을 단정하지 않습니다. 측정 근거가 있을 때만 언급합니다.
8. Agent가 요청 범위를 벗어난 경우 별도로 기록합니다. 범위 준수 문제는 기능 문제와 분리합니다.
9. 하루 종료 시 채택·보류·제외를 구분합니다. 모든 관찰을 개선으로 만들지 않습니다.
10. 협업 기록은 [Session 가이드](COLLABORATION_BETA_SESSION_GUIDE.md)에 따라 하루 하나의 Session 폴더(Page 파일, `jutell session` 명령)에 계속 이어서 작성합니다.
11. Prompt·답변 원문은 운영자가 직접 붙여 넣을 때만 로컬에 저장하며, 자동 수집하지 않습니다.

## 흐름

```
작업 실행 (JuTell로 보고)
  → 결과 검토 (실제 확인 vs 예상 구분)
  → 문제 발견 시 오늘 Session의 해당 Page `내 피드백`에 기록
      ├─ JuTell 동작·설명 문제
      ├─ Agent 실행 문제 ("Agent 실행 문제"로 표시)
      └─ 말투·표현 문제 ("말투·표현"으로 표시)
  → 반복되는 문제가 있으면 개선 제안 연결
```

## 기록할 때

- 어떤 작업, 어떤 Profile, 어떤 Feature를 썼는지 남깁니다 (Session Page 파일의 헤더와 작업 블록에 기록).
- "이전보다 나아졌다"는 비교 기록이 있어야만 판단에 씁니다.
- 한 번의 관찰로 결론을 내리지 않습니다. 같은 조건을 반복해 관찰합니다.

## 판단하지 않을 것

- JuTell 자신이 만든 평가로 JuTell의 품질을 단정하지 않습니다.
- 실험 단계에서 공식적인 "통과"를 선언하지 않습니다. 실제 테스트 전에 V0.1 통과를 선언하지 않는다는 규칙과 같습니다.
- 피드백이 쌓이기 전에 새 Feature를 만들지 않습니다.
