# Beginner Bridge Telemetry Roadmap

Telemetry는 한 번에 원격 분석으로 확장하지 않고, 로컬·투명성·동의 검토를 단계별로 통과한다.

## Phase 1 — Telemetry Policy

### 구현하는 것

* 기본 OFF 원칙
* 명시적 동의와 철회 원칙
* 수집 가능·수집 금지 정보
* 삭제와 익명 통계 원칙
* 이벤트 Registry를 정의할 문서 기반

### 구현하지 않는 것

* 이벤트 생성·저장·전송
* 동의 UI
* 서버, API, Dashboard

현재 작업은 이 단계에 해당한다.

## Phase 2 — Local Event Structure

### 구현하는 것

* Registry에 맞는 로컬 이벤트 구조
* 허용 필드 검증
* 기본 OFF와 동의 상태 확인
* 로컬 기록의 조회·삭제 설계

### 구현하지 않는 것

* 외부 전송
* 사용자·기기 식별자
* 자유 텍스트와 원문 저장
* 중앙 집계

## Phase 3 — Local Dashboard

### 구현하는 것

* 사용자가 자신의 로컬 집계만 확인하는 화면
* 기록 범위와 삭제 상태 표시
* 어떤 Feature와 검증 범주가 집계됐는지 설명

### 구현하지 않는 것

* 관리자용 원격 화면
* 다른 사용자의 기록 조회
* 자동 전송
* 개인별 행동 추적

## Phase 4 — Anonymous Analytics (Opt-in)

### 구현하는 것

* 명시적 동의 후 제한된 익명 집계 전송
* Event Registry의 허용 필드만 사용
* 전송 전 미리보기·철회·삭제 정책
* 집계 결과의 작은 집단 보호

### 구현하지 않는 것

* 기본 활성화
* Prompt, 답변, 코드, 경로 전송
* 사용자별 분석
* 동의하지 않은 사용자의 데이터 전송

## Phase 5 — Central Dashboard

### 구현하는 것

* 익명 집계만 보여주는 중앙 Dashboard
* 보존 기간과 삭제 정책
* 접근 권한과 감사 기록
* 전송 정책과 개인정보 문서 공개

### 구현하지 않는 것

* 원문 데이터 보관
* 사용자·프로젝트 역추적
* 기본 OFF를 우회하는 수집
* 문서화되지 않은 필드 수집

## Phase 6 — Team Analytics

### 구현하는 것

* 팀 단위 명시적 동의와 관리자 권한 정책
* 팀 집계와 제품 개선 지표
* 팀 탈퇴·삭제·보존 정책

### 구현하지 않는 것

* 개인별 생산성 감시
* 팀 내 개인 순위
* 동의 없는 조직 단위 수집
* Prompt나 코드 기반 평가

## 단계 전환 조건

다음 단계로 넘어가기 전 다음 항목을 문서와 검증으로 확인한다.

* 기본 OFF와 명시적 동의가 실제로 적용됨
* 허용 필드 외 데이터가 차단됨
* 삭제와 철회가 확인됨
* 재식별 위험을 검토함
* 실패 시 데이터가 전송되지 않음
* 비개발자도 정책을 이해할 수 있음
