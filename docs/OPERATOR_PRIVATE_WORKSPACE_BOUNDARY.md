# 운영자 전용 비공개 작업 공간 경계 (OPERATOR_PRIVATE_WORKSPACE_BOUNDARY)

이 문서는 공개 저장소와 운영자 전용 비공개 작업 공간의 경계를 정의한다.
공개 저장소에는 비공개 작업 공간의 **실제 이름·폴더 구조·파일 경로·수익화 전략을 기록하지 않는다**.

## 1. 경계 정의

| 구분 | 위치 | 다른 사람이 보나요? |
|---|---|---|
| 공개 저장소 | 이 저장소(`ju0o/jutell`) | 공개될 수 있음 |
| 로컬 데이터 | `.jutell-local/`, `.beginner-bridge-local/` | 운영자 로컬만 (전송·공유 안 함) |
| 운영자 전용 비공개 작업 공간 | 공개 저장소 밖 (운영자 로컬) | 운영자만 |

공개 제품은 운영자 전용 비공개 작업 공간이 존재한다는 사실에 의존하지 않는다.
작동 방식은 로컬 데이터와 공개 문서만으로 설명한다.

## 2. 공개 저장소에 기록하지 않는 것

- 비공개 작업 공간의 실제 이름
- 비공개 작업 공간의 파일 경로·폴더 구조
- 수익 목표·가격 전략·유료 전환 계획 등 비공개 전략
- 미공개 Premium 기능 목록과 우선순위
- 운영자 개인 메모와 미공개 마케팅 계획

## 3. 표현 규칙

공개 문서에서 비공개 작업 공간을 언급할 때는 **"운영자 전용 비공개 작업 공간"** 으로만 표현한다.
내용, 파일 이름, 경로는 언급하지 않는다. 일반 사용자에게 반드시 필요한 내용이 아니면 공개 README 전면에 노출하지 않는다.

## 4. 로컬 데이터와의 차이

- `.jutell-local/` — JuTell이 로컬에 생성하는 기록 (협업 Session, 설정 기록, 사용량 카운터). 공개 저장소에 추적 금지.
- 운영자 전용 비공개 작업 공간 — 운영자가 직접 작성하는 전략·개인 기록. 공개 저장소 밖에 둔다.
- 외부 검토 번들·공개 문서에는 둘 다 포함하지 않는다.

## 5. 외부 전달 경계 (export)

- 외부 검토용 전달물은 `artifacts/session-feedback/` 폴더에만 준비한다.
- 자동 생성은 기본 OFF이며, 운영자가 명시적으로 실행할 때만 만들어진다.
- Session 원본(`.jutell-local/`)은 자동으로 포함하지 않는다. 요약본만 운영자가 직접 고른다.
- 요약본에는 다음이 없어야 한다: Prompt·답변 원문, 코드·Diff 원문, 파일 경로, API Key·Token·Cookie, 실제 사용자 정보, 비공개 전략.
- 번들 생성 명령에 비공개 작업 공간 경로를 인자로 넘길 수 없다.
- 비공개 작업 공간으로 파일을 옮기는 스크립트는 공개 저장소에 만들지 않는다. 이동은 운영자가 직접 수행한다.

## 6. 검사 범위 (check:public)

공개 안전 검사(`npm run check:public`)는 다음을 탐지한다.

- 비밀정보 패턴 (API Key·Token·`sk-` 키)
- 운영자 실제 절대 경로 (Windows 드라이브 경로)
- 알려진 비공개 작업 공간 이름
- 부모 폴더 기반 상대 접근 (`path.resolve`·`join`·`relative`에 `..` 전달)
- 실제 Session 원본·로컬 데이터 (금지 경로 추적)
- 비공개 전략 문서 (파일명·폴더 규칙)
- Review Bundle 보관본 (`artifacts/*.zip` 안 금지 항목)

## 7. 예외(allowlist)

위험이 아님을 직접 확인한 경우에만 예외를 기록한다.
`scripts/check-public-repository.mjs`의 `ALLOWED_EXCEPTIONS`에 다음 네 가지를 함께 적는다.

- 파일 경로
- 탐지 유형 (예: `winPath`)
- 예외 이유
- 허용 범위

검사 규칙 자체의 문자열(탐지 패턴)과 저장소 루트 계산(`..` 사용)은 예외로 기록되어 있다.
예외는 해당 파일의 해당 탐지에만 적용되며 다른 검사를 끄지 않는다. 두 검사 스크립트(`check-public-repository.mjs`·`create-review-bundle.mjs`)에 같은 예외를 기록한다.
