# 운영자 피드백 폼 (Operator Feedback Form)

아래 폼을 복사해서 Dashboard의 베타 기록에 붙여 넣고 채웁니다. **기록에는 Prompt, 코드, 파일 경로, 오류 원문, 프로젝트 식별 정보, 비밀정보를 넣지 않습니다.**

```
# 피드백 기록

## 1. 작성일
YYYY-MM-DD

## 2. 작성자
(이름 또는 별명)

## 3. 사용한 Profile
[ ] `minimal`  [ ] `balanced`  [ ] `learning`  [ ] `detailed`

## 4. 작업 종류
(예: 문서 수정, 설정 변경, 코드 리뷰, 실험 실행)

## 5. 사용한 화면/도구
[ ] Skill (자동 보고)  [ ] Dashboard  [ ] MCP  [ ] CLI  [ ] Request Builder  [ ] 기타: ____

## 6. 사용한 기능
(어떤 기능을 사용했는지. 예: 변경 요약, 용어 설명, 위험 안내)

## 7. 편했던 점
(구체적으로 한 문장 이상)

## 8. 불편했던 점
(구체적으로 한 문장 이상)

## 9. 이해하기 어려웠던 표현
(표현 그대로 적지 말고, 어떤 뜻을 몰랐는지 요약해서)

## 10. 잘못된 보고/오류
[ ] 오류를 관찰함 (동작이 멈춤, 오류 메시지)  [ ] 잘못된 보고 (사실과 다른 내용)  [ ] 없음

## 11. 개선 아이디어
(있다면. "이런 게 있으면 좋겠다" 수준으로)

## 12. 심각도
[ ] 낮음 (불편하지만 계속 사용 가능)  [ ] 보통 (자주 부딪힘)  [ ] 높음 (사용을 멈춤)

## 13. 다시 사용할 의향
[ ] 다시 쓸 것  [ ] 다시 쓸 수도 있음  [ ] 다시 안 쓸 것

## 14. 기타
(위 항목에 없는 내용)

## 15. 기록 규칙 확인
[ ] 비밀정보·경로·프로젝트 식별 정보를 넣지 않았다
[ ] 실제로 확인한 것과 예상을 구분해 적었다

## 16. 처리 상태
[ ] 새 기록  [ ] 검토 중  [ ] 반영 대기  [ ] 반영됨  [ ] 보류  [ ] 기각

## 17. 관련 화면/문서
(이 기록이 어느 화면이나 문서와 연결되는지. 있으면 적고, 없으면 생략)

## 18. 다음 행동
(누가 무엇을 하면 되는지. 예: "다음 작업에서 길이를 줄여 보고 다시 기록")
```

## 작성 요령

- 한 건에 한 가지 문제를 기록합니다.
- 심각도는 그날의 기분이 아니라 **반복 여부**로 정합니다. 두 번 이상 부딪히면 보통 이상입니다.
- "오류"와 "취향 차이"를 구분합니다. 취향 차이는 사용을 막지 않는다면 낮은 심각도입니다.
- 기록 후 처리 상태는 `새 기록`으로 시작하고, 이후 검토할 때 갱신합니다.
