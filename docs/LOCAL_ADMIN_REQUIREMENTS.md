# 로컬 관리자 화면 요구사항과 V0.1 구현 범위

## 문서 범위

이 문서는 한 명의 프로젝트 운영자가 로컬에서 Beginner Bridge 설정과 개인 베타 기록을 관리하기 위한 요구사항과 V0.1 구현 범위입니다. 현재 구현은 `apps/local-admin/`에 있으며, 향후 개선 시 이 문서를 기준으로 합니다.

기본 동작은 인터넷 연결 없이 가능해야 합니다. 중앙 서버, 계정, 로그인, API, Gateway, MCP, Plugin, Electron은 이 요구사항의 전제가 아닙니다.

## 목표

로컬 관리자 화면은 다음을 쉽게 해야 합니다.

- `.beginner-bridge.json` 설정을 확인하고 바꾸기
- Profile과 Feature를 바꾸기
- 제한값을 확인하고 안전한 범위에서 바꾸기
- 저장 전에 최종 설정을 미리 보기
- 기본 설정으로 되돌리기
- 개인 베타 기록을 보고 직접 작성하기
- 로컬 기록을 모두 삭제하기
- 선택형 로컬 MCP 서버 실행·중지와 Codex 연결 준비 상태 확인

## 화면 요구사항

### 개요

현재 Profile, 활성·비활성 Feature 수, 제한값, Skill 버전, 마지막 설정 변경 시각을 보여줍니다. 프로젝트 이름과 경로는 자동으로 보여주지 않습니다.

### Feature

각 Feature의 ID, 쉬운 설명, ON/OFF 상태, 꺼졌을 때 생략되는 정보, 안전상 항상 보고되는 예외를 보여줍니다. 사용자가 안전 필드를 끄는 것처럼 오해하지 않도록 예외를 분명히 표시합니다.

### Profile

네 Profile을 보여주고 현재 Profile, Profile 간 차이, 변경 전 미리보기를 제공합니다. 명시적 Feature와 limits가 Profile보다 우선한다는 규칙도 함께 안내합니다.

### 제한값

`maxMainFiles`(1~10), `maxGlossaryTerms`(0~10), `compactReportMaxSentences`(4~30)의 현재값과 허용 범위를 보여줍니다. 범위를 벗어난 값은 저장하지 않으며 기본값 복원 기능을 제공합니다.

일반 사용자는 숫자를 직접 판단하지 않아도 되도록 `최소·보통·많이`, `사용 안 함·조금·보통·많이`, `매우 짧게·짧게·보통·자세히` 중에서 선택할 수 있습니다. 숫자 입력은 고급 설정 안에 두며, 일반 사용자는 바꾸지 않아도 됩니다.

### 개인 베타 기록

운영자가 익명 프로젝트 별칭, Profile, 유용했던 Feature, 불편했던 Feature, 길이, 이해하기 어려운 표현, 잘못된 보고서, 개선 아이디어, 심각도와 처리 상태를 직접 기록하고 봅니다. 실제 프로젝트 이름과 경로를 자동으로 수집하지 않습니다.

### 로컬 이벤트

향후 Telemetry의 로컬 이벤트 구조를 보여줄 수 있는 자리만 남깁니다. 현재 이벤트 생성·저장·전송은 구현하지 않습니다.

### 현재 V0.1 실행 범위

`apps/local-admin/`은 Node 로컬 API와 Vite 화면을 함께 실행합니다. 설정·Profile·Feature·limits 조회와 저장, 기본값 복원, 설정 기록 삭제, 개인 베타 피드백의 작성·수정·개별 삭제·전체 삭제, 선택형 로컬 MCP 서버와 Codex 프로젝트 설정 관리를 제공합니다. MCP 도구는 읽기 전용이며 로컬 이벤트와 원격 Telemetry는 여전히 구현하지 않습니다.

관리자 화면은 현재 Codex 세션을 자동으로 바꾸지 않습니다. `.beginner-bridge.json`을 저장한 뒤 Codex가 `AGENTS.md`, `SKILL.md`, 설정 파일을 읽도록 작업 요청에 안내해야 하며, 화면은 이 준비 상태를 직접 확인할 수 있게 보여줍니다. 화면의 보고서 적용 확인은 세션에 이미 적용됐다는 뜻이 아니라 수동 확인이 필요하다는 뜻입니다.

MCP 연결도 세 상태를 나눕니다. 로컬 서버 실행, `.codex/config.toml` 등록, 실제 Codex 도구 호출은 서로 다릅니다. 실제 호출을 확인하지 못하면 연결 완료가 아니라 `Codex 세션에서 직접 확인 필요`로 표시합니다.

### 개인정보

다음 내용을 한 화면에서 확인할 수 있어야 합니다.

- 외부 전송 여부
- 현재 로컬에 저장된 자료
- 저장하지 않는 자료
- 전체 삭제 방법
- 설정 파일 위치
- 미래 원격 Telemetry에는 별도 동의가 필요하다는 점

## 저장 데이터 설계

V0.1에서 저장하는 것은 다음뿐입니다.

- Profile과 Feature 설정
- 사용자가 직접 작성한 개인 베타 피드백
- 설정 변경 시각
- 사용자가 입력한 익명 프로젝트 별칭
- Skill 버전
- 사용자가 선택한 작업 분류
- MCP 사용 여부와 운영체제 자동 시작 여부

저장 위치는 프로젝트 루트의 `.beginner-bridge.json`과 `.beginner-bridge-local/`입니다. 사용자는 Privacy 화면에서 위치와 삭제 기능을 확인할 수 있습니다.

## 절대 저장하지 않는 데이터

Prompt, AI 답변, 코드, Git diff, 파일 경로, 프로젝트 이름, Repository URL, 환경변수, 컴퓨터 계정 이름, API Key, 비밀번호, Token, Cookie, 원문 오류 로그를 자동으로 저장하지 않습니다. 사용자가 오류 요약을 직접 적을 때도 민감한 값을 먼저 제거해야 합니다.

## 구현 원칙과 후보

구현 시 다음 원칙을 만족해야 합니다.

- localhost에서만 동작
- 인터넷·외부 계정·로그인·서버 API 없이 사용 가능
- 설정 저장 전 미리보기와 형식 검증 제공
- 설정 오류 시 안전한 기본값 사용
- 기록 전체 삭제 제공
- 코드, Prompt, AI 답변을 읽거나 저장하지 않음
- Electron을 필수로 만들지 않음

V0.1은 `Vite + React` 화면과 Node.js 기본 HTTP 서버를 `apps/local-admin/`에서 사용합니다. 외부 UI 프레임워크는 사용하지 않습니다. 다음 버전에서 기술을 바꿀 때도 Windows 사용 편의, 간단한 설치, 오프라인 동작, 안전한 JSON 편집, 향후 오픈소스 공개 가능성, 테스트 용이성으로 비교해야 합니다.

## 범위 밖

중앙 Dashboard, 원격 Telemetry 전송, 팀 분석, 계정과 권한, 결제, 배포, 자동 코드 분석, Prompt·코드 수집, 자동 이벤트 저장은 이 문서만으로 구현을 시작하지 않습니다.

## 구현 시작 전 확인 기준

- 설정 파일이 손상되거나 사라지지 않는지
- 잘못된 값이 저장되지 않는지
- Profile과 Feature 변경 결과를 저장 전에 볼 수 있는지
- 모든 로컬 기록을 삭제할 수 있는지
- 개인정보 화면이 실제 저장 범위와 일치하는지
- 인터넷 없이 실행되는지
- 기존 Beginner Bridge 보고 규칙과 충돌하지 않는지

## V0.1 검증 범위

- API와 Vite 화면이 `127.0.0.1`에만 열리는지
- 설정과 피드백 저장이 허용된 로컬 위치에만 일어나는지
- 설정 변경 전 미리보기와 확인 절차가 표시되는지
- 잘못된 설정과 잘못된 limits를 거부하는지
- 저장 실패 시 기존 설정이 유지되는지
- 개인 베타 사용 중 실제로 이해하기 쉬운지
