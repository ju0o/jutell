# JuTell Telemetry Policy

## 1. 목적

Telemetry는 사용자를 추적하기 위한 기능이 아니다.

JuTell의 어떤 보고 기능이 자주 사용되는지, 설정 오류나 검증 실패가 어느 범주에서 발생하는지처럼 제품을 개선하는 데 필요한 제한적인 정보를 이해하기 위한 구조다.

이 문서는 이벤트 이름과 허용 필드의 정책만 정의한다. 현재 버전에서는 이벤트를 생성하거나 저장하거나 전송하지 않는다.

## 2. 기본 OFF

Telemetry는 기본적으로 비활성화한다.

사용자가 명시적으로 동의하기 전에는 다음을 하지 않는다.

* 이벤트 생성
* 이벤트 로컬 저장
* 외부 전송
* 익명 통계 계산을 위한 별도 기록

동의는 보고서 기능 사용 동의와 묶지 않는다. 사용자가 어떤 Profile이나 Feature를 사용하더라도 Telemetry 동의로 해석하지 않는다.

사용자는 언제든 Telemetry를 끌 수 있어야 한다. 끈 뒤에는 새 이벤트를 만들지 않으며, 이후 단계에서 저장 기능이 생기면 기존 기록 삭제 방법도 함께 제공해야 한다.

## 3. 사용자 동의

동의는 다음 조건을 만족해야 한다.

* 무엇을 왜 수집하는지 먼저 설명한다.
* 수집 가능한 필드와 수집하지 않는 정보를 공개한다.
* 미리 선택된 동의로 간주하지 않는다.
* 동의하지 않아도 JuTell의 보고 기능을 사용할 수 있다.
* 동의를 철회하는 방법을 제공한다.

V0.1에서는 동의 화면이나 명령을 구현하지 않는다. 이후 구현이 추가되더라도 명시적 동의 전송 금지 원칙은 유지한다.

## 4. 로컬 우선

V0.1에서는 모든 Telemetry를 로컬 이벤트 구조로만 정의한다.

다음은 구현하지 않는다.

* 이벤트 파일 또는 JSON 로그
* 데이터베이스
* 중앙 서버
* API, Gateway, Provider
* 웹 UI, 관리자 대시보드
* 자동 전송이나 원격 분석

향후 로컬 기록이 추가되더라도 이벤트 Registry의 허용 필드만 기록한다.

## 5. 익명 통계 원칙

향후 통계를 만들 때도 개별 사용자를 식별하거나 행동 이력을 따라가지 않는다.

* 사용자별 ID, 기기 ID, 세션 ID를 만들지 않는다.
* 개별 이벤트보다 집계된 횟수와 비율을 우선한다.
* 작은 집단을 역추적할 수 있는 세부 분류는 제공하지 않는다.
* 이벤트에 기록되지 않은 값을 다른 데이터와 결합해 식별하지 않는다.
* 원문이나 자유 입력을 통계 계산에 사용하지 않는다.

익명이라는 표현은 단순히 이름을 빼는 것만을 뜻하지 않는다. 다른 정보와 결합해 사용자를 알아낼 수 있는 구조도 피해야 한다.

## 6. 데이터 최소 수집

수집 가능한 정보는 `docs/TELEMETRY_EVENTS.md`의 Registry에 명시된 필드로 제한한다.

허용 범위는 다음과 같다.

* JuTell 버전
* Skill 버전
* Profile 이름
* 활성·비활성 Feature ID
* 설정 변경 이벤트
* 보고서 생성 이벤트
* 검증 성공·실패와 제한된 검증 종류
* 제한된 설정 오류 범주
* 운영체제 종류

이벤트에는 자유 텍스트, 명령 원문, 오류 로그, 파일 목록, 시간·위치·기기 식별값을 넣지 않는다.

## 7. 절대 수집하지 않는 정보

다음 정보는 로컬 기록과 향후 원격 확장 모두에서 수집 대상에서 제외한다.

* 프로젝트 코드와 파일 내용
* Git diff
* Prompt
* AI 답변 원문
* 파일 경로
* 프로젝트 이름
* Repository URL
* API Key와 환경 변수 값
* 비밀번호, Token, Cookie
* 개인정보, 이메일, 사용자 이름
* 사용자 입력과 검색어
* 인증·권한·결제 정보
* 오류 메시지, 스택 트레이스, 명령 출력 원문

## 8. 데이터 삭제

V0.1에서는 저장을 구현하지 않으므로 삭제할 Telemetry 데이터도 없다.

향후 저장이 추가되면 다음을 제공해야 한다.

* 저장된 이벤트 전체 삭제
* Telemetry 비활성화 후 새 기록 중단
* 삭제 완료 여부 확인
* 백업이나 원격 복사본의 보존 기간 공개
* 삭제할 수 없는 기록이 있다면 그 이유와 범위 공개

삭제 요청을 사용자 계정이나 프로젝트 식별과 연결하지 않는 방향을 우선한다.

## 9. 미래 확장 원칙

로컬 기록, 익명 통계, 관리자 대시보드로 확장할 수 있지만 각 단계 전에 다음을 다시 확인한다.

* 기본 OFF와 명시적 동의
* 허용 필드 목록과 최소 수집
* 삭제 방법
* 재식별 가능성
* 보존 기간
* 실패 시 안전한 동작

확장 단계는 `docs/ROADMAP_TELEMETRY.md`에서 정의한다.

## 10. 현재 범위 밖

다음은 이 문서의 정책 대상이지만 이번 작업에서 구현하지 않는다.

* 실제 이벤트 생성
* 로컬 이벤트 저장
* 익명화 처리 프로그램
* 원격 전송
* 중앙 서버와 API
* Gateway, Electron, 웹 UI
* 관리자 페이지와 Dashboard
* 팀별 분석과 사용량 수집
