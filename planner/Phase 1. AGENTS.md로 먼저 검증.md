## Phase 1. AGENTS.md로 먼저 검증

처음부터 Skill을 만들지 않는다.

우선 실험할 프로젝트 하나에 AGENTS.md를 추가해서 Codex가 지침을 제대로 따르는지 확인한다.

Codex는 프로젝트 루트부터 현재 작업 디렉터리까지 AGENTS.md를 읽으며, 더 가까운 디렉터리의 지침이 앞선 지침보다 우선한다. 
기본 합산 제한은 32KiB이므로 항상 적용할 규칙은 짧게 유지해야 한다.

# AGENTS.md에 들어갈 핵심 규칙

아직 코드를 작성하는 게 아니라 다음 규칙의 효과를 검증한다.

```

1. 사용자를 비개발자로 간주한다.
2. 개발 용어가 처음 등장하면 바로 쉬운 뜻을 붙인다.
3. 작업 완료 후 기술 보고서와 별도 보고서를 중복 생성하지 않는다.
4. 하나의 최종 답변 자체를 비개발자용으로 작성한다.
5. 수정된 파일마다 역할을 한 문장으로 설명한다.
6. 사용자가 보는 화면의 변화와 내부 코드 변화를 구분한다.
7. 위험, 미확인 항목, 직접 테스트할 내용을 구분한다.
8. 실제 확인하지 않은 결과를 성공했다고 단정하지 않는다.

```

# Phase 1 테스트

실제 프로젝트에서 Codex에게 세 종류 작업을 맡긴다.

```

테스트 A: 버튼 색상 변경
테스트 B: 로그인 기능 수정
테스트 C: API 연결 추가

```

그리고 다음을 평가한다.

쉬운 설명인가
의미가 왜곡되지 않았는가
지나치게 길지 않은가
수정 파일이 정확한가
테스트하지 않은 내용을 구분했는가
다음에 무엇을 해야 하는지 알 수 있는가
