## Phase 4. 쉬운 변경 보고서

여기가 첫 번째 실사용 버전이야.

Codex가 작업을 마친 뒤 Skill이 다음 보고서를 생성한다.

# 고정 출력 구조

```

1. 이번 작업 한 줄 설명
2. 왜 이 작업을 했는가
3. 사용자 화면에서 달라지는 점
4. 내부적으로 달라진 점
5. 수정된 기능
6. 수정된 파일과 각 파일의 역할
7. 삭제되거나 새로 생긴 것
8. 영향받을 수 있는 기존 기능
9. 실제 실행한 검증
10. 아직 확인하지 못한 것
11. 사용자가 직접 확인할 항목
12. 최종 판정

```

# 용어 설명 규칙

모든 단어를 괄호로 설명하면 오히려 읽기 어려워져.

그래서 다음 원칙으로 간다.

```

IDE(코드를 작성하고 실행하는 작업 공간)
API(프로그램끼리 정보를 주고받는 연결 통로)
GUI(사용자가 눈으로 보고 클릭하는 화면)
컴포넌트(화면을 구성하는 재사용 가능한 조각)
라우트(특정 주소의 요청을 처리하는 경로)

```

처음 등장할 때만 설명
같은 답변에서 반복 설명하지 않음
정확성을 훼손할 정도로 단순화하지 않음
꼭 필요한 용어만 사용
용어를 완전히 없애지 않고, 원래 용어도 함께 보여줌

“GUI = AI와 대화하는 공간”처럼 특정 프로젝트에서만 맞는 설명은 피해야 해. GUI는 더 넓게 사용자가 눈으로 보고 조작하는 화면으로 설명해야 다른 프로젝트에서도 정확해.
