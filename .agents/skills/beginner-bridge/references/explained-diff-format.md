# JuTell — Explained Diff Format Reference

`explainedDiff` Feature가 활성일 때, 의미 있는 변경을 비개발자가 이해할 수 있는 형식으로 설명하는 규칙이다. 기존 6개 보고 항목을 대체하지 않는다. 변경 요약·내부 변화·주요 파일 설명에 이미 모인 근거를 다시 사용해 설명을 덧붙이며, 별도의 보고 체계나 용어 체계를 만들지 않는다.

## 1. 적용 조건

* `.jutell.json`의 `explainedDiff`가 켜져 있을 때만 적용한다.
* 모든 작업에 적용하지 않는다. 다음 중 하나에 해당하는 의미 있는 변경에만 사용한다.
  * 기능 동작이 달라진 경우
  * 사용자 화면이나 사용 방법이 달라진 경우
  * 데이터 저장·처리 방식이 달라진 경우
* 문구 한 개, 색상 한 곳처럼 단순 작업은 기존 보고 형식만으로 충분하다.
* 코드나 Diff 원문 자체를 요청받아 설명할 때는 `report-format.md`의 코드·Diff 설명 규칙과 함께 이 형식을 사용한다.

## 2. 출력 형식

```md
[무엇을 바꿨나요?]
<비개발자 언어로 한두 문장>

[왜 바꿨나요?]
<확인된 변경 이유 또는 아래 3번 문구>

[어디를 바꿨나요?]
- `<파일>` — <역할 한 문장>

[실제 중요한 변경]
- <기능 단위로 묶은 중요한 변경>
```

`내가 직접 다듬고 싶다면?` 항목은 4번 조건을 만족할 때만 마지막에 추가한다.

## 3. 환각 방지 규칙

근거 없는 내용을 확인된 사실처럼 쓰지 않는다. 이것이 이 형식의 최우선 규칙이다.

### 3.1 왜 바꿨나요?

변경 이유는 다음 근거로만 작성한다.

* Agent 작업 결과에 기록된 변경 목적
* 사용자 요청 문장
* 코드 비교로 직접 확인한 변경 전후 차이

위 근거가 없으면 추측하지 않고 다음처럼 표시한다.

> 변경 이유는 Agent 결과에서 확인되지 않았습니다.

파일 이름만으로 변경 이유를 만들어내지 않는다.

### 3.2 무엇을 바꿨나요?와 실제 중요한 변경

* 실제 읽거나 비교한 변경 범위 안에서만 작성한다.
* 파일명만으로 파일 역할이나 기능 효과를 단정하지 않는다.
* 실행하지 않은 동작은 "예상"으로 구분한다.

### 3.3 어디를 바꿨나요?

* `mainFiles`와 같은 주요 파일 선정 규칙을 따른다. 단순 작업 최대 3개, 일반 작업 최대 5개.
* 관련된 파일은 하나의 논리적 변경으로 묶어 함께 표시한다.

## 4. 내가 직접 다듬고 싶다면?

일반 코딩 안내가 아니라, 이번 변경과 연결된 위치만 알려준다. 다음처럼 코드에서 직접 확인한 단순 수정 지점에만 제시한다.

| 대상 | 예시 |
|---|---|
| 버튼·표시 문구 | 해당 컴포넌트의 라벨 문자열 |
| 색상 | 해당 스타일 값 또는 디자인 변수 |
| 여백·간격 | 해당 화면의 간격 값 |
| 이동 경로 | 연결된 페이지 경로 또는 링크 |
| 간단한 화면 동작 | 해당 컴포넌트의 표시 조건 |

규칙:

* 코드 근거가 없으면 이 항목을 만들지 않는다. 억지로 채우지 않는다.
* 인증, 권한, 결제, 데이터베이스 처리 같은 영역은 간단한 다듬기 대상으로 제시하지 않는다. 대신 "이 부분은 간단한 화면 수정 대상이 아니라 주의가 필요한 변경입니다."처럼 표시한다.
* TypeScript 문법 강의, React 줄별 해설처럼 구현 세부를 가르치지 않는다.

## 5. 묶기와 길이

* 관련된 변경은 기능 단위로 묶는다. 파일마다 다섯 항목을 반복하지 않는다.
* 전체 Diff 원문을 다시 출력하지 않는다. 중요한 변경 블록만 요약한다.
* [실제 중요한 변경]은 확인된 핵심 동작 위주로 작성하고, 같은 내용을 다른 보고 항목에서 반복하지 않는다.
* 기존 보고서 길이 규칙(`compactReportMaxSentences`, 작업 규모별 길이)이 우선한다. 설명을 붙인다고 길이 제한을 무시하지 않는다.

## 6. 예시

합성 예시이며 실제 프로젝트가 아니다.

```md
[무엇을 바꿨나요?]
검색 버튼이 빈 입력 상태에서도 눌리던 문제를 고쳤습니다.

[왜 바꿨나요?]
빈 검색어로 실행되면 결과 없는 화면만 보여줬기 때문입니다.

[어디를 바꿨나요?]
- `src/features/search/SearchBar.tsx` — 검색창 입력과 버튼을 담당하는 파일

[실제 중요한 변경]
- 검색어가 비어 있으면 검색 버튼이 실행되지 않음
- 검색어를 다시 입력하면 버튼이 원래대로 활성화됨
```

코드에서 버튼 문구 위치를 직접 확인했다면 마지막에 다음을 추가한다.

```md
[내가 직접 다듬고 싶다면?]
버튼 문구는 `SearchBar.tsx`의 버튼 라벨 부분에서 바꿀 수 있습니다.
```

변경 이유를 확인할 근거가 없었다면 `[왜 바꿨나요?]`에는 "변경 이유는 Agent 결과에서 확인되지 않았습니다."라고만 쓴다.
