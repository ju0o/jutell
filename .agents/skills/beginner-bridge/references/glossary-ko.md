## 1. 화면과 코드 구조

### GUI

GUI(사용자가 눈으로 보고 클릭하거나 입력하는 프로그램 화면)

### CLI

CLI(터미널에 명령어를 입력해 프로그램을 사용하는 방식)

### IDE

IDE(코드를 작성하고 실행하는 개발 도구)

주의: Codex가 파일을 읽고 수정하는 실행 환경을 자동으로 IDE라고 부르지 않는다.

### Component

Component(화면이나 기능을 구성하는 독립적인 코드 조각)

적용 조건: 프로젝트가 Component 구조를 사용하는 것이 확인된 경우에만 사용한다.

### Props

Props(React Component에 전달되는 값)

적용 조건: React 프로젝트에서만 사용한다.

### Hook

Hook(React의 상태나 기능을 재사용하기 위한 기능)

적용 조건: React 프로젝트에서만 사용한다.

### Event

Event(클릭이나 입력처럼 프로그램에서 발생한 동작이나 신호)

문맥에 따라 사용자 동작인지 시스템 신호인지 확인한다.

### Handler

Handler(특정 동작이 발생했을 때 실행되는 기능)

### State

State(화면이나 기능이 현재 가지고 있는 값이나 상태)

현재 프로젝트에서 입력값, 로그인 상태, 검색 진행 상태 중 무엇을 뜻하는지 확인한다.

### Layout

Layout(화면 요소를 배치하는 구조)

## 2. 서버와 데이터

### API

API(프로그램끼리 정보를 주고받는 연결 통로)

### Endpoint

Endpoint(API 요청을 보내거나 받는 구체적인 주소)

### Request

Request(프로그램에 작업이나 정보를 요청하는 것)

### Response

Response(요청에 대해 프로그램이 돌려주는 결과)

### Server

Server(요청을 받아 처리하고 결과를 돌려주는 프로그램)

### Client

Client(서버에 요청을 보내고 결과를 사용하는 프로그램이나 화면)

### Database

Database(프로그램의 정보를 저장하고 관리하는 시스템)

### Schema

Schema(데이터가 어떤 항목과 구조로 저장되는지 정한 규칙)

### Query

Query(데이터를 조회하거나 변경하기 위해 보내는 요청)

### Migration

Migration(데이터베이스 구조를 변경하고 적용하는 작업)

### Cache

Cache(다시 사용할 정보를 빠르게 가져오도록 임시로 저장하는 기능)

### 입력 검증

입력 검증(입력한 값이 필요한 조건에 맞는지 먼저 확인하는 기능)

시나리오 B에서는 다음 의미를 유지한다.

> 검색어가 필요한 조건에 맞는지 검색 실행 전에 먼저 확인하는 기능

### Dependency

Dependency(프로젝트가 사용하기 위해 의존하는 다른 코드나 패키지)

### Package

Package(설치해서 사용할 수 있도록 묶어 놓은 코드와 설정)

### Framework

Framework(프로그램을 일정한 구조로 만들도록 도와주는 개발 기반)

### Library

Library(특정 기능을 가져다 사용할 수 있는 코드 모음)

## 3. 로그인과 보안

### Authentication

Authentication(사용자가 누구인지 확인하는 과정)

한국어 보고서에서는 `인증(Authentication, 사용자가 누구인지 확인하는 과정)`처럼 쓸 수 있다.

### Authorization

Authorization(확인된 사용자가 어떤 기능을 사용할 수 있는지 판단하는 과정)

한국어 보고서에서는 `권한 확인(Authorization, 사용자가 해당 기능을 사용할 수 있는지 판단하는 과정)`처럼 쓸 수 있다.

### Session

Session(여러 요청을 같은 사용자나 작업의 흐름으로 연결하는 정보)

로그인 문맥에서는 로그인 상태를 일정 시간 유지하는 정보라는 뜻으로 설명할 수 있다.

### Token

Token(인증이나 접근 권한을 확인할 때 사용하는 값)

실제 Token 값은 보고서에 출력하지 않는다. 현재 프로젝트에서 다른 용도로 사용되면 그 문맥을 우선한다.

### Cookie

Cookie(브라우저가 로그인 상태나 설정을 기억하기 위해 저장하는 작은 정보)

### Middleware

Middleware(요청과 실제 기능 사이에서 추가 확인이나 처리를 하는 중간 기능)

처리가 실행 전인지, 실행 후인지, 요청과 응답 모두에 적용되는지 현재 코드를 확인한다.

### Permission

Permission(사용자가 특정 기능을 사용할 수 있는 권한)

### Secret

Secret(외부에 공개하면 안 되는 민감한 값)

예: API 키, 비밀번호, 접근 토큰, 인증 쿠키, 연결 문자열.

### Environment Variable

Environment Variable(코드 밖에서 설정값이나 비밀 값을 전달하는 방식)

실제 값은 보고서에 표시하지 않고 변수 이름만 표시한다.

## 4. 실행과 검증

### Runtime

Runtime(프로그램이 실제로 실행되는 환경)

### Build

Build(작성한 코드를 실행하거나 배포할 수 있는 형태로 준비하는 과정)

### Compile

Compile(작성한 코드를 다른 실행 가능한 형태로 바꾸는 과정)

### Unit Test

Unit Test(작은 기능 하나가 올바르게 작동하는지 확인하는 자동 테스트)

### Integration Test

Integration Test(여러 기능이 연결됐을 때 함께 작동하는지 확인하는 테스트)

### Lint

Lint(코드 형식이나 잠재적인 문제를 자동으로 검사하는 도구)

### Type Check

Type Check(코드에서 사용하는 값의 종류가 서로 맞는지 검사하는 과정)

### Refactoring

Refactoring(기능을 바꾸지 않는 것을 목표로 코드 구조를 정리하는 작업)

Refactoring 후 기능이 실제로 유지됐는지는 별도 검증이 필요하다.

## 5. Git과 변경

### Diff

Diff(수정 전과 수정 후의 차이)

### Commit

Commit(Git에 변경 내용을 하나의 기록으로 저장하는 것)

### Branch

Branch(코드 변경을 분리해 작업하는 개발 흐름 또는 기록)

Branch를 실제 별도 폴더나 작업 공간으로 설명하지 않는다.

### Merge

Merge(분리해서 작업한 변경 내용을 하나의 흐름으로 합치는 작업)

## 6. 배포와 운영

### Deploy

Deploy(프로그램을 실제 사용 가능한 환경에 반영하는 작업)

### Production

Production(실제 사용자가 이용하는 운영 환경)

### Staging

Staging(실제 배포 전에 운영 환경과 비슷하게 시험하는 환경)

### Hosting

Hosting(웹사이트나 프로그램을 실행할 공간을 제공하는 서비스)

### Domain

Domain(사용자가 웹사이트에 접속할 때 사용하는 주소)

### Rollback

Rollback(문제가 생긴 변경을 이전 상태로 되돌리는 작업)

### Log

Log(프로그램에서 발생한 동작, 상태 또는 오류를 기록한 내용)

## 7. 문맥 주의 용어

다음 용어는 하나의 정의로 고정하지 않는다.

| 용어 | 확인할 문맥 |
|---|---|
| Route | 웹 페이지 주소, 서버 API 경로, 화면 이동 규칙 중 무엇인지 확인 |
| State | 입력값, 로그인 상태, 화면 표시 상태 등 무엇을 기억하는지 확인 |
| Event | 사용자 동작인지 시스템 신호인지 확인 |
| Session | 로그인 유지 정보인지, 일반 작업 흐름인지 확인 |
| Token | 인증 토큰인지, 다른 용도의 식별 값인지 확인 |
| Middleware | 요청 전 처리인지, 요청·응답을 함께 처리하는지 확인 |

문맥을 확인하지 못하면 다음과 같이 표시한다.

> 이 용어가 현재 프로젝트에서 정확히 어떤 역할을 하는지는 확인하지 못했습니다.

## 잘못된 설명을 피하는 예

| 피해야 할 표현 | 권장 방향 |
|---|---|
| GUI는 AI와 대화하는 공간이다 | GUI는 사용자가 보고 조작하는 프로그램 화면이다 |
| Database는 컴퓨터의 머리다 | Database는 정보를 저장하고 관리하는 시스템이다 |
| Middleware는 요청을 가로채는 계층이다 | Middleware는 요청과 기능 사이에서 추가 처리를 하는 중간 기능이다 |
| Branch는 별도 작업 폴더다 | Branch는 변경을 분리하는 개발 흐름 또는 기록이다 |
| 입력 검증은 Submit handler에 guard를 넣는 것이다 | 입력한 값이 조건에 맞는지 실행 전에 확인하는 기능이다 |
